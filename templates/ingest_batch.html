Ingest a batch into {{ journal.name }}

One PDF per chapter. Each is read, cleaned and filed as a draft article, the same way ingest_volume.py does it from a terminal. A chapter takes a few minutes, so this runs as a background job: you can close the page and come back to it.

This is destructive to anything it replaces, and it is inference. Where a PDF carries no structure tree the paragraphs, headings and emphasis are read off the geometry of the page, and every one of those is a judgement that can be wrong. Check what comes out.

Up to {{ shape.max_files }} files, {{ shape.max_mb }} MB in total. A collected volume sitting beside its chapters is recognised by its length and left out. Chapter order comes from the filename where it carries a number; where it does not, the chapters sort by name and you can set the order afterwards.

What this batch is

Stamped into every chapter's front matter. Leave them empty for an archive that is not organised by volume.

Licence

The default, and for an archive you did not publish it is the only safe one. A chapter prints its own terms on its opening page and ingest recovers them; stamping one licence across a batch overwrites that. Volume 1 of Writing Spaces is the reason this is a choice: twelve of its chapters permit derivatives and five do not, so one value across the run published the wrong terms over twelve of them.

Only used when the box above is unticked. The jurisdiction is part of the URL; a 3.0 United States licence is not a 4.0 International one.

How to handle what is already here

Off by default. A re-ingest rebuilds the body from the PDF, so any alt text, long description or metadata typed since the first ingest is rewritten unless the pipeline carries it. Descriptions and the four carried fields are carried; anything else is not, and .versions/ keeps only the last five.

By default a chapter with a Teacher Resources section renders it as a second galley. Tick this to leave it in the chapter.
